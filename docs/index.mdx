Uniform Resources (UR, [BCR-2020-005](https://github.com/BlockchainCommons/Research/blob/master/papers/bcr-2020-005-ur.md)) encode binary payloads as URI-friendly `ur:<type>/<bytewords>` strings for QR codes and unreliable channels. Multi-part transfer uses a GF(2) fountain: any subset of parts that reaches full rank reconstructs the message.

## Packages

| Package    | Registry  | Language             |
| ---------- | --------- | -------------------- |
| `@qntx/ur` | npm       | TypeScript           |
| `bcur`     | crates.io | Rust                 |
| `bcur-cli` | crates.io | Rust (`bcur` binary) |

## Layers

| Layer | Contents                                     | Spec                                                                                                          | TypeScript                          | Rust                                |
| ----- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------- | ----------------------------------- |
| L1    | Bytewords, identifiers, bytemoji             | [BCR-2020-012](https://github.com/BlockchainCommons/Research/blob/master/papers/bcr-2020-012-bytewords.md)    | `@qntx/ur`                          | `bcur::bytewords`, `bcur::bytemoji` |
| L2    | GF(2) fountain over opaque bytes             | [BCR-2024-001](https://github.com/BlockchainCommons/Research/blob/master/papers/bcr-2024-001-multipart-ur.md) | `FountainEncoder`/`FountainDecoder` | `bcur::fountain`                    |
| L3    | `ur:` URIs, encoders, decoders               | [BCR-2020-005](https://github.com/BlockchainCommons/Research/blob/master/papers/bcr-2020-005-ur.md)           | `UrEncoder`/`UrDecoder`             | `bcur::ur`                          |
| L4    | dCBOR values, codecs                         | dCBOR ([I-D.dcbor](https://datatracker.ietf.org/doc/draft-mcnally-deterministic-cbor/))                       | `@qntx/ur/typed`                    | `bcur::typed` (`dcbor` feature)     |
| L5    | Registry types (seed, hdkey, descriptors, …) | [BCR-2020-006](https://github.com/BlockchainCommons/Research/blob/master/papers/bcr-2020-006-urtypes.md)      | `@qntx/ur/registry`                 | —                                   |

The registry layer (L5) is TypeScript-only in this release.

The L1–L3 transport treats payloads as opaque bytes; the dCBOR requirement of BCR-2020-005 is enforced at L4, not on the wire transport.

## Conformance

Both implementations run the same frozen vector files under `vectors/`: official BCR and URKit/bc-ur vectors, generated part-CBOR and decoder-frame streams, registry vectors, and v1→v2 conversion expectations. `parity.json` tracks which capabilities each language covers and which tests exercise them. A seeded differential test (`bun run test:parity`) generates randomized encoder/decoder sessions in TypeScript and replays them frame-by-frame in Rust.
