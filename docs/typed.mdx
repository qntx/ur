---
title: Typed UR
description: L4 dCBOR Uniform Resources on @qntx/ur/typed.
---

`@qntx/ur/typed` is L4: the first dCBOR parse in this package. L1–L3 stay opaque bytes plus a type token. Root `@qntx/ur` does not import dcbor.

Requires optional peer `@blockchaincommons/dcbor@1.0.0-beta.3`. dcbor requires Node `>=22.12`. Importing `@qntx/ur/typed` without the peer fails at load.

```ts
import { Ur } from "@qntx/ur/typed";

const ur = Ur.create("test", [1, 2, 3]);
ur.string(); // "ur:test/lsadaoaxjygonesw"

const again = Ur.fromUrString(ur.string());
```

`Ur.create` maps a JS value through dCBOR. The UR body is untagged. Application codecs use `UrCodec`: `tags[0].name` is the UR type token written; every `tag.name` is accepted on read; `untaggedCbor` / `fromUntaggedCbor` are the body.

```ts
import { toUr, fromUr, type UrCodec } from "@qntx/ur/typed";
import { cbor, expectText, Tag, type Cbor } from "@blockchaincommons/dcbor";

const noteCodec: UrCodec<{ text: string }> = {
  tags: [Tag.from(40_000, "note")],
  untaggedCbor: (n) => cbor(n.text),
  fromUntaggedCbor: (value: Cbor) => ({ text: expectText(value) }),
};

const ur = toUr({ text: "hi" }, noteCodec);
fromUr(ur, noteCodec);
```

`MultipartEncoder.create(ur, maxFragmentLength)` encodes dCBOR **once**, then uses L3 `Encoder`. `MultipartDecoder.message()` dCBOR-parses recovered bytes. `CborDecode` on `message()` is not session poison.

`@qntx/ur/typed` does not ship application types. v2 `seed` / `hdkey` / `keypath` / `coin-info` / `sskr` / `psbt` / `envelope` live on `@qntx/ur/registry`, whose codecs also accept the deprecated v1 `crypto-*` tokens on read.

L3 UTF-8 `"hello"` remains valid transport. `Ur.fromUrString` of that URI throws `CborDecode`.
