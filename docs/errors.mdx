title: Errors
description: The unified error model — UrError codes and ErrorKind variants are one-to-one.
---

TypeScript throws `UrError`; Rust returns `Error` with a `kind()`. Codes and variants are one-to-one, and the fatal set is identical. `ErrorKind` is `#[non_exhaustive]`: match with a wildcard arm.

| TS `UrError.code`          | Rust `ErrorKind`           | Fatal | Meaning                                                                 |
| -------------------------- | -------------------------- | ----- | ----------------------------------------------------------------------- |
| `NonAscii`                 | `NonAscii`                 | no    | Bytewords string is not ASCII                                           |
| `InvalidWord`              | `InvalidWord`              | no    | Unknown or malformed byteword                                           |
| `InvalidBytewordsLength`   | `InvalidBytewordsLength`   | no    | Bytewords length inconsistent with the style                            |
| `InvalidBytewordsChecksum` | `InvalidBytewordsChecksum` | no    | Trailing CRC-32 does not match                                          |
| `InvalidScheme`            | `InvalidScheme`            | no    | Missing `ur:` scheme                                                    |
| `TypeUnspecified`          | `TypeUnspecified`          | no    | No type token after the scheme                                          |
| `InvalidType`              | `InvalidType`              | no    | Empty or illegal type token                                             |
| `InvalidIndices`           | `InvalidIndices`           | no    | Bad `seq-count` header or mismatch with the part                        |
| `UnexpectedType`           | `UnexpectedType`           | no    | Type not in the accept list / differs from the locked type              |
| `InvalidPartCbor`          | `InvalidPartCbor`          | no    | Malformed fountain-part CBOR                                            |
| `InvalidPart`              | `InvalidPart`              | no    | Zero/empty part fields or inconsistent padding                          |
| `InconsistentPart`         | `InconsistentPart`         | no    | Part conflicts with earlier frames                                      |
| `ResourceLimit`            | `ResourceLimit`            | yes   | A decoder budget was exceeded (`limit`/`Limit` detail)                  |
| `InvalidPadding`           | `InvalidPadding`           | yes   | Non-zero padding past the message length                                |
| `InvalidMessageChecksum`   | `InvalidMessageChecksum`   | yes   | Joined payload failed CRC-32                                            |
| `EmptyMessage`             | `EmptyMessage`             | no    | Fountain encoder given an empty message                                 |
| `InvalidFragmentLength`    | `InvalidFragmentLength`    | no    | Fragment bounds not positive, or `min > max`                            |
| `MessageTooLong`           | `MessageTooLong`           | no    | Message exceeds the `u32` wire length field                             |
| `NotSinglePart`            | `NotSinglePart`            | no    | Single-part API used on a multi-part UR                                 |
| —                          | `NotComplete`              | no    | `into_decoded()` on an unfinished decoder (Rust only; TS reads `state`) |
| `CborDecode`               | `CborDecode`               | no    | Payload is not well-formed deterministic CBOR (L4)                      |
| `CborType`                 | `CborType`                 | no    | Well-formed CBOR that does not fit the codec's shape (L4/L5)            |
| `Internal`                 | `Internal`                 | yes   | Internal invariant broken                                               |

## Inspecting errors

TypeScript narrows detail by `code`; `UrError.info` is a discriminated union:

```ts
import { UrError } from "@qntx/ur";

try {
  // …
} catch (error) {
  if (error instanceof UrError) {
    if (error.info.code === "ResourceLimit") {
      error.info.limit; // "messageLength" | "fragmentCount" | "fragmentLength" | "uriLength"
    }
    if (error.info.code === "UnexpectedType") {
      error.info.expected; // accepted UrType[]
      error.info.found; // the mismatched type
    }
    error.fatal; // session-fatal for a decoder
  }
}
```

Rust reads detail through accessors:

```rust
use bcur::{Error, ErrorKind};

match error.kind() {
    ErrorKind::ResourceLimit => { let _ = error.limit(); } // Option<Limit>
    ErrorKind::UnexpectedType => {
        let _ = error.expected_types(); // &[UrType]
        let _ = error.found_type();     // Option<&UrType>
    }
    _ => {}
}
let fatal = error.is_fatal();
let inner = core::error::Error::source(&error); // Some(&dcbor::Error) for CborDecode/CborType
```

`Limit` implements `Display` with human-readable text (`message length`, `fragment count`, `fragment length`, `URI length`), so a `ResourceLimit` error reads `resource limit exceeded: message length`.
