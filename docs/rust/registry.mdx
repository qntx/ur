The registry crate maps application values to dCBOR bodies on dcbor's tagged traits. Every type's `cbor_tags()` is `[v2 tag, v1 tag]`: **v2 tags are written, v1 tags are read-only** (BCR-2020-006 `crypto-*` types are deprecated). Wire forms, defaults, and accept/reject behavior are shared with the [TypeScript registry](../typescript/registry.mdx); the Rust API is idiomatic — domain types carry invariants, constructors are checked, and optional fields are `Option`.

```bash
cargo add bcur-registry
cargo add bcur --features dcbor # to_ur / from_ur live on bcur's typed layer
```

```rust
use bcur::typed::{UrDecodable, UrEncodable};
use bcur_registry::Seed;

let seed = Seed::new(vec![0xc7; 16]).unwrap();
let ur = seed.to_ur().unwrap(); // ur:seed/… (v2 tag name)
let back = Seed::from_ur(&ur).unwrap(); // accepts ur:seed and ur:crypto-seed
assert_eq!(seed, back);
```

## Types

| v2 UR type           | v2 tag | v1 read type       | v1 tag | Type                                  |
| -------------------- | ------ | ------------------ | ------ | ------------------------------------- |
| `seed`               | 40300  | `crypto-seed`      | 300    | `Seed`                                |
| `hdkey`              | 40303  | `crypto-hdkey`     | 303    | `HdKey` = `MasterKey` or `DerivedKey` |
| `keypath`            | 40304  | `crypto-keypath`   | 304    | `Keypath`                             |
| `coin-info`          | 40305  | `crypto-coin-info` | 305    | `CoinInfo`                            |
| `eckey`              | 40306  | `crypto-eckey`     | 306    | `EcKey`                               |
| `address`            | 40307  | `crypto-address`   | 307    | `Address`                             |
| `output-descriptor`  | 40308  | `crypto-output`    | 308    | `OutputDescriptor`                    |
| `sskr`               | 40309  | `crypto-sskr`      | 309    | `SskrShare`                           |
| `psbt`               | 40310  | `crypto-psbt`      | 310    | `Psbt`                                |
| `account-descriptor` | 40311  | `crypto-account`   | 311    | `AccountDescriptor`                   |

All maps are closed: an unknown map key is an `Error::UnknownKey`, a missing required key is `Error::MissingKey`, and a wrong CBOR major type is `Error::Cbor`. Validation runs identically on encode (checked constructors) and decode. Embedded tagged values — `CoinInfo` inside `HdKey` or `Address`, `Keypath` inside `HdKey` — accept both v1 and v2 tags on read and always write v2.

## Construction

Values are built by checked `new` constructors returning `Result` where validation is needed, plus consuming `#[must_use]` `with_*` builders for optional fields. Invariants live in the types: key material is a fixed-size array (`[u8; 33]`, `[u8; 32]`), a fingerprint is `Fingerprint([u8; 4])`, a BIP-32 child index is `Index(u32)` bounded to `uint31`, hardened-ness is part of `ChildNumber`/`ChildRange`, and the wire alternatives are enums (`HdKey`, `PathComponent`, `AddressType`, `Curve`, `DescriptorKey`).

```rust
use bcur_registry::{
    ChildNumber, CoinInfo, CoinType, DerivedKey, Fingerprint, HdKey, Index, Keypath,
    Network, PathComponent,
};

let index = |v| Index::new(v).unwrap();
let origin = Keypath::new(
    vec![
        PathComponent::Child(ChildNumber::Hardened(index(84))),
        PathComponent::Child(ChildNumber::Hardened(index(0))),
        PathComponent::Child(ChildNumber::Hardened(index(0))),
    ],
    Some(Fingerprint::from(0x73c5_da0a_u32.to_be_bytes())),
    None,
)
.unwrap();

let hdkey = HdKey::from(
    DerivedKey::public(pub_key_data) // pub_key_data: [u8; 33]
        .with_use_info(CoinInfo::new(CoinType::BTC, Network::MAINNET))
        .with_origin(origin)
        .with_parent_fingerprint(Fingerprint::from(0x73c5_da0a_u32.to_be_bytes()))
        .unwrap()
        .with_name("account"),
);
```

## Validation rules

- **seed**: `payload` 1–64 bytes, required. `with_creation_date(dcbor::Date)` writes CBOR tag 1 (epoch seconds) and reads tag 1 or tag 100 (epoch days). `with_name`/`with_note` set optional text; `""` normalizes to absent and is never written.
- **coin-info**: `CoinType` is `uint31` (`CoinType::BTC`, `CoinType::ETH`), `Network` is `i32` (`Network::MAINNET`, `Network::TESTNET`). Both default and are omitted on write when default.
- **keypath**: `components` is a a `Vec` of `PathComponent` (`Child`, `Range`, `Wildcard`, `Pair`; `Pair` is one 4-tuple on the wire). `source_fingerprint` is an optional `Fingerprint` — a zero fingerprint is rejected (`uint32 .ne 0`); `depth` is an optional `u8`. A fully vacuous keypath (no components, fingerprint, or depth) is rejected.
- **hdkey**: `MasterKey::new([u8; 33], [u8; 32])` — a master key is always private, so `key_data` must carry the `0x00` prefix. `DerivedKey::public([u8; 33])` or `DerivedKey::private([u8; 33])` — private key data carries the `0x00` prefix. Builders: `with_chain_code`, `with_use_info`, `with_origin`, `with_children`, `with_parent_fingerprint` (rejects zero), `with_name`, `with_note`.
- **eckey**: `EcKey::private(Curve, data)` / `EcKey::public(Curve, data)`; `curve` is `Curve::Secp256k1` (wire 0, omitted on write) or `Curve::Other(u64)` — any `u64` is accepted. secp256k1: private keys are exactly 32 bytes, public keys 33 or 65 bytes. Other curves: non-empty data.
- **address**: `Address::p2pkh`/`p2sh`/`p2wpkh` take a 20-byte hash; `Address::untyped(data)` requires non-empty bytes. `with_info(CoinInfo)` writes a v2-tagged coin-info under key 1.
- **psbt**: `Psbt::new(bytes)` requires the PSBT magic `70 73 62 74 ff`; `into_bytes` and `AsRef` expose the payload.
- **sskr**: `SskrShare::new(SskrHeader { .. }, value)` — `group_threshold`, `group_count`, `member_threshold` in 1–16; `group_index` in 0–15 and `< group_count`; `member_index` in 0–15; `group_threshold <= group_count`. The share is a packed 5-byte header plus the value bytes.
- **output-descriptor**: `OutputDescriptor::new(source, keys)` — the `@n` placeholders in `source` must be exactly the set `0..keys.len()` (no gaps, no extras; no placeholders means `keys` is empty), else `Error::Placeholders`. `keys` is a a `Vec` of `DescriptorKey` (`HdKey`, `EcKey`, or `Address` written as their v2 tagged CBOR). `with_name`/`with_note` optional text.
- **account-descriptor**: `AccountDescriptor::new(Fingerprint, first)` always holds at least one `OutputDescriptor` (more via `with_output_descriptor`); a zero `master_fingerprint` is allowed (BCR-2023-019).

## Errors

Constructors and the `TryFrom` conversion from `CBOR` fail with the crate's `Error` — a `#[non_exhaustive]` enum with self-contained context:

- `Cbor(dcbor::Error)` — a structural failure (wrong major type, malformed input); the only variant with a `source()`;
- `UnknownKey { key }` / `MissingKey { key }` — closed-map violations;
- `UnexpectedTag { tag }` — a tag the type does not accept (untagged input is `Cbor(WrongType)`);
- `InvalidLength { field, len }`, `OutOfRange { field }`, `Invalid { field, reason }` — semantic validation;
- `Placeholders` — a bad `@n` placeholder set;
- `UnsupportedScript { tag }` — a v1 script expression that cannot be represented.

`Display` is lowercase with no trailing period (e.g. `payload length 65 is outside the allowed range`). The `From` conversion into `dcbor::Error` passes `Cbor(e)` through unchanged and wraps every other variant as `dcbor::Error::Custom` with the `Display` text, so `CBORTaggedDecodable` keeps the full message.

## v1 output/account conversion

`crypto-output` bodies are BCR-2020-010 script-expression trees (tags 400–410: `sh` `wsh` `pk` `pkh` `wpkh` `combo` `multi` `sortedmulti` `raw` `tr` `cosigner`). On read the converter emits BIP-380 descriptor text:

```rust
use std::str::FromStr;

use bcur::Ur;
use bcur::typed::UrDecodable;
use bcur_registry::OutputDescriptor;

let ur = Ur::from_str("ur:crypto-output/taadmutaadeyoyaxhdclaoswaalbmwfpwekijndyfefzjtmdrtketphhktmngrlkwsfnospypsasrhhhjonnvwtsqzwljy").unwrap();
let descriptor = OutputDescriptor::from_ur(&ur).unwrap();
assert_eq!(descriptor.source(), "pkh(@0)");
// descriptor.keys() re-encodes each key with its v2 tag
```

The emitted functions are exactly:

- key functions: `pk(@n)`, `pkh(@n)`, `wpkh(@n)`, `combo(@n)`, `cosigner(@n)`;
- wrappers: `sh(…)` and `wsh(…)`, combinable only as `sh(wsh(…))` per BIP-380 (`sh` is top-level only; `wsh` is top-level or directly inside `sh`);
- multisig: `multi(k,@n,…)` and `sortedmulti(k,@n,…)`;
- `raw(<lowercase hex>)` (carries no key) and `tr(@n)` (BIP-386 single-key form only).

Keys become `@0`, `@1`, … in order of appearance and are collected as `DescriptorKey` values (a v1 `307` address nested inside a script function becomes an `address` key, not an `addr()` function). A bare key expression directly inside `sh`/`wsh` — the KeystoneHQ form `sh(key)` — is read as `sh(cosigner(@0))`. Anything unconvertible — a `tr()` script tree, `sh` inside `sh` or `wsh`, `wsh` inside `wsh` — is `Error::UnsupportedScript` (surfaced through `TryFrom`) or a `dcbor::Error::Custom` at the `CBORTaggedDecodable` boundary.

`crypto-account` converts the same way through `AccountDescriptor`; entries may carry the `308` tag or be bare script expressions (KeystoneHQ writes the latter). Conversion and nesting edge cases are pinned by `vectors/registry/crypto-output-conversion.json` and `vectors/registry/invalid.json`.

## Secrets

`Seed`, `MasterKey`, `DerivedKey`, and `SskrShare` zeroize secret material on drop (`ZeroizeOnDrop`) and redact it in `Debug` (`[REDACTED]`). `EcKey` zeroizes `data` on drop and redacts it in `Debug` only when `is_private()`.

## Digests

[BCR-2021-002](https://github.com/BlockchainCommons/Research/blob/master/papers/bcr-2021-002-digest.md) object digests:

```rust
seed.digest(); // [u8; 32] — SHA-256 of the raw payload bytes
hdkey.digest(); // [u8; 32] — SHA-256 of the dCBOR digest preimage
hdkey.digest_source(); // Vec<u8> — dCBOR [keyData, chainCode|null, coinType, network]
```

## Tag tables

`bcur_registry::tags` exposes a `dcbor::Tag` constant for every UR type and script expression (`tags::SEED`, `tags::CRYPTO_SEED`, `tags::SH`, `tags::MULTI`, `tags::TR`, …). `register_tags()` installs all 31 names into dcbor's global tag store for diagnostic output; `register_tags_in(&mut store)` registers them on an explicit `TagsStore`.

## Envelope

The `envelope` UR type (tag 200) is not part of `bcur-registry`; use Blockchain Commons' [`bc-envelope`](https://crates.io/crates/bc-envelope) crate.
